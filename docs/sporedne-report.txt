Evidence and changes
- TrafficData previously contained only six corridor paths; no side routes.
- The supplied generated asset's eastern Tuđmana corridors are only ~1.7 km long,
  ending at the Krešimira crossroads around gx -4419. GraphRoad cannot follow its
  unnamed through edge. The editor step now uses the package's two continuous
  eastern main-lane paths (~5.58 km each), retaining the s13 works gap. This is
  traffic path data; the road meshes are not rebuilt by this change.
- Package coordinates must first pass through paket-approaches.json's affine
  transform, then W.U (Unity x=gx+4200, z=-(gz+5300)). Treating package x/z as game
  coordinates would put every turn in the wrong place.
- The editor matches each route's heading, level and endpoint to a corridor lane,
  corrects the handoff over 15 m, and follows the imported surface with raycasts.
  A rejected mouth stops Build traffic before saving the asset/scene.
- Existing model signal groups and generic side-approach stop lines gate entry.
  Side cars stop before the connector, accept at least four seconds of clearance
  PLUS connector traversal/acceleration time, and include every main lane and the
  player's truck. Reservations make main-road IDM see an approaching merge;
  late gap changes can revoke it before crossing. This deliberately favours long
  waits over aggressive merging. Left turn-ins also wait for opposing traffic.
- Only passenger vehicles <=6 m take stubs. Existing indicators are reused.
  Bodies/colliders, instanced drawing, LODs and materials use the existing pool.
  A visible finite exit end holds the car until the conservative visibility test
  permits removal; the car never extrapolates beyond the street's mapped end.

Editor/build steps (for the coordinator)
1. Let Unity compile, then run Magistrala/Build traffic and save its scene/data.
   The same menu also regenerates the existing car meshes/materials, as before.
   No separate menu or external lane file is needed: the reviewed subset is
   Assets/Editor/sporedne-routes.json. Its original source hash is recorded there.
2. Check the build log for [sporedne] built 20 mouths and no rejected sources.
   Rebuild the player after generating TrafficData.asset.
3. Use -sporedne 1 (default) and -sporedne 0 in that same rebuilt player for A/B.
   Both use the extended eastern corridors. Existing -trafpk25 and -trafring
   remain available. The normal ring/fade/despawn defaults remain
   700–1200 / 850–1050 / 1300 m, 64 cars, 25-degree view margin.
4. Read [sporedne] once per game minute: entries/min = completed merges,
   exits/min = completed side-street removals, blocked-merges/min = refused
   inbound gap/signal checks (a waiting car may be counted repeatedly).
   The startup line reports enabled state, route count and the shared budget.

Expected cost (estimate, not measured)
- Total count stays within the existing budget of 64. Up to six active side cars;
  four pool slots are reserved near side routes so main spawns do not starve them.
- Nine local 512 m buckets refreshed once a second; no per-frame full stub scan.
  Only active cars participate in simulation/gap checks. Spawn attempts <=1/3 s.
- About 0.2 MB additional path arrays; editor source subset is ~62 KB.
  No new rendering pipeline or per-junction GameObjects. The more varied visible
  cars may change existing material/LOD draw counts. CPU/FPS cost is unmeasured;
  expect a small simulation increase, with occasional cover-raycast spikes.

Untested / open issues
Unity compilation, editor menu execution, actual collider heights/curbs, camera
framing, spawn-cover success, turn radii, truck yielding in both directions,
queues/reservation behaviour, signal timing, red-light counters, FPS and pop-in
A/B are all untested. No Unity process was started. In particular review the
3.5–3.8 m lateral D8 slip handoffs and generic signal approach matches visually.
Finite ends can remain occupied while visible; conservative reservations can
produce long waits. This is a stub implementation, not full network routing.
The existing D8 corridor's eastern endpoint is not extended in this change.
